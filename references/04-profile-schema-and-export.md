# 04｜多档案管理、跳槽换壳与导出分享规范

> 本架构实现「**1 套个人表达内核（第 1/2 层）＋ N 套场景视觉皮肤（第 3 层）**」，兼顾零门槛单档案起步与职场多场景扩展。

---

## 一、全局档案目录结构（`~/.ppt-style/`）

所有跨项目持久化的风格档案、历史版本快照与文档留底快照均存放在全局隐藏目录 `~/.ppt-style/` 中，**绝不污染用户的业务工作文件夹**：

```text
~/.ppt-style/
├── registry.json                     # 最近活跃工坊指针、默认激活档案 ID、安装路径
├── snapshots/<doc_id>/               # 全自动只读出稿底稿库（含语义指纹、>50MB 已剥离视频）
├── backups/                          # 旧版技能备份区（绝不放在全局 skills/ 同级目录）
└── profiles/
    └── <profile_id>/                 # 默认为 default
        ├── core_l1_planning.json     # 第 1 层：页面规划规则（与公司模板解耦的个人能力内核）
        ├── core_l2_content.json      # 第 2 层：单页内容组织与表达规则（个人能力内核）
        ├── masks/                    # 第 3 层：N 套可命名的视觉皮肤面具
        │   ├── default.json          # 默认视觉规则（字体、色板中文名与色值、留白网格、母版路径）
        │   └── <mask_id>.json        # 可选拆出的子面具（如“对外客户提案”“对内极简周报”）
        └── history/                  # 每次更新规则前的自动版本快照，支持一键回滚
```

---

## 二、五大常见管理操作流程（全有大白话口令）

### 1. 按需拆分场景面具（`split-mask`）
- **何时触发**：不在开局强制用户建多套。仅当第 2 步扫描检测到代表作明显分成两派（如深色大图提案 vs 白底高密表格），或用户主动说“我要单独建一套对外提案风格”时触发。
- **做法**：保留并共享同一套第 1/2 层表达内核，只把不同的配色、板式、留白和是否保留品牌 Logo 拆成独立的第 3 层视觉面具；用户日后只需说“用我的对外提案风格来写”即可秒切。

### 2. 跳槽换新公司模板（`swap-visual-shell`）
- **用户痛点**：换了新东家、换了强制使用的企业母版，但多年练就的逻辑框架和表达手感不想重头再来。
- **做法**：调用 `workspace_manager.py profile swap-visual-shell`——先自动保存当前版本快照以防误操作，随后**锁定保留全部第 1/2 层个人习惯**，仅重置指定面具的第 3 层视觉壳，并引导用户丢入 1 份新公司空白模板或 1～2 份新公司范例重采视觉规范。

### 3. 查看、删除单条学歪的习惯（`delete-rule`）
- 用户说“看看你记了哪些我的习惯”或“删掉第 3 条习惯”时，用大白话按编号列出当前第 1/2/3 层生效规则（绝不吐 JSON 原文）；确认编号后先做版本快照再删除，同时刷新 `00-操作中心.md` 与 `03-我的PPT风格说明书.md`。

### 4. 回滚上个版本 / 恢复出厂设置（`rollback` / `reset`）
- **回滚版本**：直接恢复至 `history/` 中上一次操作前的完整档案快照；
- **恢复出厂设置**：先做一次最后安全快照，再清空当前工坊进度与个人规则库，回到干净初始状态。

### 5. 按需打包导出独立分享包（`export-share`）
- **设计定位**：平时自己用只需常驻单一主技能 `PPT-style`；当用户想把自己的某一风格（如团队规范版）分享给新同事时，执行导出：
  - 将目标档案对应的三层规则文件（经过 `sanitize-rule` 脱敏确认无个人敏感数据）＋ `PPT-style` 运行框架打包成一个独立自包含目录；
  - 提示用户“把这个文件夹发给同事，对方双击安装就能直接按这套风格写 PPT”。
