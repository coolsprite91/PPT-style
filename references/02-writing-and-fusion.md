# 02｜日常 5 档口语化写 PPT、参考融合与多轮手改时间线（V0.2.0）

> 适用场景：风格建档完成后，日常按场景/档位写 PPT、自由混搭皮肤、临时借鉴外部参考，以及多轮人机交替手改回流。

---

## 一、每次调用的组合解析与首行身份回执（硬规定）

每次收到写 PPT 请求时，先按用户的口头场景与皮肤需求调用：
```bash
python3 "<skill_dir>/scripts/workspace_manager.py" profile resolve-combo --scenario "<场景名>" [--mask "<指定皮肤>"]
```
回复**第一行必须先亮明当前接管的三层组合身份**：
- 示例：`【已按你的个人风格（例会与进展汇报 · 浅色蓝主题皮肤）接管 · 档位 1：全套代写】`

---

## 二、5 档口语化输入追问与输出合同

> **通用缺口铁律**：缺必需输入就先停下来，像靠谱同事对接一样用大白话一次性列出缺口，**首行必须报明精确问题总数**；第 1/2/3 档缺资料停机时，固定置顶 **`0. 赶时间先标 [待补]，直接帮我把全稿/草稿出完`** 逃生开关。

### 档位 1｜全套代写（“按我的 XX 风格做一套 PPT”）
- **缺口口语追问模板**：
  > “好嘞，我按你的风格从头帮你做。开工前就差 **2 件事**（直接大白话发我就行）：
  > 1. 这份 PPT **给谁看、想达成什么目的**？（比如给管理层同步进度、拉通方案拍板，还是给外部受众做提案）
  > 2. 把你手头的**相关文档、数据表或零散要点**发我；如果对总页数或公司模板有硬要求也顺带提一句。
  > *(0. 赶时间的话直接回 `0`，缺数据的地方我先标 `[待补]`，先把整套架子和草稿给你搭出来)*”
- **执行**：一（页面规划）→ 二（单页内容）→ 三（排版出稿）串联，每层停顿确认。

### 档位 2｜只做页面规划（“先帮我规划分几页、每页讲什么”）
- **缺口口语追问模板**：
  > “没问题，咱们先把架子搭出来。只要告诉我 **2 件事**就能开工：
  > 1. 这次汇报**给谁看、重点想讲清什么**？
  > 2. 你大概打算覆盖**哪几块内容**？（不用给很细的数据，列几个主题或丢份粗纲就行；有固定页数限制也告诉我）
  > *(0. 想先看一版参考架子直接回 `0`)*”
- **执行**：调用 L1 场景规划节奏，输出《页面规划单》（含总页数、逐页结论骨架与进第 2 层建议补齐的素材清单）。

### 档位 3｜按大纲填内容（“这几页大纲定了，把每页写出来”）
- **缺口口语追问模板**：
  > “收到，我会严格按你定的页数和结构来写，不乱拆改。开工前请把这 **2 样东西**给我：
  > 1. 你定好的**逐页大纲**（一共几页、每页要讲什么主题）；
  > 2. 对应每页的**具体材料、数字或案例**（要是哪几页纯粹讲观点或品牌案例、不需要严谨数据，顺口提一句就行，我不会拿时间口径硬卡它；需要顺手写演讲口播词也说一声）。
  > *(0. 资料还没齐、想先搭文字底稿直接回 `0`，缺数的地方我帮你标 `[待补]`)*”
- **执行**：调用 L2 该场景下的多套单页框架＋表达习惯，区分“数据举证页”与“对外主张/品牌页”；备注高占比自动开启台面要点＋讲者口播双通道。

### 档位 4｜定稿只美化排版（“文字定稿了，一字不改按我风格重排”）
- **缺口口语追问模板**：
  > “明白，我保证文字和数字一字不改，只帮你排好看。发我这 **2 样**就行：
  > 1. 已经**分好页的定稿文字**（或你写好字的粗糙 PPT 草稿）；如果给的是一整篇还没分页的长文档，先停下来问一句：‘这是整篇长文还没分页，要先帮你切好页再一字不改排版吗？’
  > 2. 这次要套你档案里的**哪套模板皮肤**（或者顺手丢一份参考模板/要用到的原图截图给我）。”
- **执行**：
  1. 强制跑 `snapshot_diff.py verify-text-lock`（允许美观拆框，对数字/单位/金额/百分比/正负大小于号零容忍全等校验，代码公式白名单豁免）；
  2. `pptx_builder.py` 按本机安全字体估算字宽并留 12%～15% 余量，超载停机报页数；
  3. 缺 `python-pptx` 时按三句话显式降级确认，拒绝安装则交付带清晰布局建议的逐页文案稿，**绝不手拼 XML 损坏文件**。

### 档位 5｜旧稿局部加页或原地改页（“在这份第 X 页后加两页 / 只改第 X 页”）
- **缺口口语追问模板**：
  > “放心，除了你指定的地方，别的页面我一动不动。告诉我这 **3 句话**就行：
  > 1. 原 PPT 文件是哪一份？（直接拖进来或给路径）
  > 2. 具体要在**第几页后面加几页**，或者**只改哪一页**？
  > 3. 新加或要改的这几页，具体要写什么内容（或把相关资料丢给我）？默认我会自动对齐前后两页的画风，有特殊要求再说。”
- **执行**：调用 `pptx_builder.py build --mode patch`，支持 `insert_after_slide` 插页与 `replace_slides` 原地替换指定页，**锁死其余原页 100% 不动**，并自动继承原文件隐形编号。

## 三、临时参考材料融合（按层绑定 ＋ 主题自洽派生）

1. 导入 1 份或多份参考（`.pptx` / PDF / 截图）时，先给 1 道单选确认借鉴范围：
   `1. 全套借鉴 / 2. 只借视觉配色版式 / 3. 只借分页与内容结构`（多份参考可分绑不同层；PDF/截图明告无法读出精确字体名，改用本机相近安全字体）。
2. **主题自洽派生**：同层冲突无条件用参考；参考未覆盖的元素（如深色参考里没有表格），只借个人表格结构逻辑，配色对比度与文字密度顺应参考稿色板与留白；动笔前强制剔除他司 Logo、页脚与旧数字，先输出 3～5 行《本轮风格融合结论》且仅本轮生效。

## 四、多轮人机交替手改时间线（`revisions[]`）

完整支持 **`AI 建稿(R1) → 人手改(H1) → AI 接着改(R3) → 人再手改(H2) → 定稿`** 全过程：

1. **AI 续改自动补抓人改（不丢稿）**：只要在用户改过的稿子上跑 `pptx_builder.py` 续改/局部改，脚本会先继承原 `doc_id`，自动检测并把用户上一轮磁盘手改抓成一条 `human_edit` 快照存档，绝不吞掉前轮手改。
2. **单轮增量检查与推进检查点**：用户说“我改好了”时，调用：
   ```bash
   python3 "<skill_dir>/scripts/snapshot_diff.py" diff --pptx "<手改文件>" --mode latest [--mark-reviewed]
   ```
   - 自动按语义对齐增删页、过滤保存时间戳/WPS 碎片/1pt 微动；
   - 确认完当前轮次后推进已审检查点（`mark-reviewed`），下一轮继续手改时**只报新增改动，绝不重复翻旧账**。
3. **项目最终收口（纯人工修改汇总）**：多轮交替完成后若想一次性沉淀长期习惯，调用：
   ```bash
   python3 "<skill_dir>/scripts/snapshot_diff.py" diff --pptx "<最终定稿>" --mode cumulative_human
   ```
   - 仅统计所有 `human_edit` 区间，**自动剔除中间 AI 自己改的段落**，绝不把 AI 的改动误学成用户偏好。
4. **防占锁写盘 ＋ 防误学确认单**：Windows 下文件正开着时自动另存 `-v2.pptx`；确认单第一行永远置顶 **`0. 这次是临时应急调整，千万别记入我的长期风格`**。

## 五、固定范式调用查询通道

当用户问“怎么发起写 PPT”“怎么调用我的风格”“有哪些口令”“怎么用 PPT-style”时，运行：
```bash
python3 "<skill_dir>/scripts/workspace_manager.py" usage-guide
```
原样按其返回的 5 段固定结构回答（资产速览 → 按场景直接发起 → 5 档怎么开口 → 自由混搭与临时参考 → 手改进化与反悔口令）。
